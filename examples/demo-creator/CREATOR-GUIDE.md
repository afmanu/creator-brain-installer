# Creator guide

## Load order

1. Read `CREATOR-CONTEXT.md` for every creator-dependent task.
2. Read only the module files relevant to the current request.
3. Use `.creator-brain/profile.json` or `.creator-brain/sources.json` only when structured detail or provenance is needed.

## Operating rules

- Apply confirmed profile values within their recorded scope.
- Preserve the creator's positioning, audience, voice and claim boundaries.
- Distinguish creator evidence, external evidence and model suggestions.
- Do not invent personal experience, opinions, results, customers or stories.
- Do not imply publication, scheduling or external action without an explicit separate request and approval.
- Ask only when a missing fact would materially change the result; otherwise use a reversible declared assumption allowed by the creative contract.
- Treat source metadata as provenance, not permission to reopen a source.
- Never store conversation content automatically.

## Content workflow

For a creator request:

1. identify the intended audience, outcome, channel and format;
2. select relevant positioning, voice, strategy and knowledge fields;
3. separate supported claims from ideas requiring research or confirmation;
4. create a draft consistent with the creative contract;
5. check the result against quality criteria and prohibited patterns;
6. clearly surface unresolved decisions.

## Profile updates

Do not silently learn from normal conversation. When feedback suggests a durable change:

1. identify the affected field;
2. show the current and proposed value;
3. explain the evidence and downstream projections affected;
4. obtain approval;
5. update the structured profile;
6. recompile affected Markdown and adapters;
7. validate and record the change.

## Boundaries

Creator Brain is a creative profile, not an operational content database. Do not create calendars, queues, campaign state or publication records inside it.
